## 本次新增

| 项目 | 实现与边界 |
| --- | --- |
| Meow 鸿蒙网络层 | TCP/UDP 在 connect/send 前绑定物理 netId；绑定失败终止连接；DNS 客户端复用公共 socket 工厂，补齐 AnyTLS 和 Hysteria2 路径。递归 bootstrap 使用鸿蒙网络专属 DNS API，阻止重新进入 VPN；阻塞解析最多 4 个，调用有超时。 |
| sing-box 鸿蒙网络层 | 从实际物理 netId 读取接口、地址和 DNS；初始化 sing-box 的接口列表与默认接口；DNS 使用物理网络提供的服务器，socket 绑定失败中止。原平台适配没有填充接口列表，实测会在握手前报 `no available network interface`。 |
| HTTP-obfs 兼容 | sing-box HTTP 模式先发送 Shadowsocks 目的地址，匹配当前 Mihomo 的 eager 路径；独立适配器支持跨包 HTTP 头、只有响应头的首包、短写和响应头大小上限。TLS-obfs 保持原实现。 |
| 标准协议转换 | SS、SOCKS、HTTP、VMess、VLESS、Trojan、Hysteria2、TUIC，以及支持范围内的 TLS、Reality、uTLS、WebSocket、gRPC、HTTP/H2 字段。未知协议、传输、插件和无法等价转换的规则进入不兼容清单。配置转换不等于所有协议均已真机验收。 |
| 内核决策与准入 | 同时约束内核版本、构建指纹、配置指纹和节点指纹；按能力、已导入验收及失败冷却筛选。自动候选优先级固定为 sing-box、Meow，最终保留 Mihomo。手动选择保存偏好，未通过准入时实际仍回退。 |
| 启动健康检查 | 使用实际内核拥有的专属入口访问 HTTPS，检查状态和应用返回字节。另行检查所选 GLOBAL 节点的物理 bootstrap DNS、TCP 可达性；UDP 协议不伪装成 TCP 测试。TCP 可达不代表协议认证，认证由经代理成功返回 HTTPS 证明；规则模式可能使用另一节点。 |
| 自动回滚 | 候选启动探测失败后清理所属会话，再恢复基线；失败冷却 5 分钟；较新的停止或切换意图优先，旧探测不会重启已被用户停止的 VPN。 |
| 诊断 | 导出实际会话、构建/配置/节点指纹、启动分层检查及允许名单内的原生连接方向和字节数。原生 ring log 有容量上限，正常关闭时保存最近会话；不能把它当作 SIGKILL 的发送方证据。 |
| 公平测试工具 | 独立入口：Mihomo 18490、Meow 18491、sing-box 18492；验证实际进程、会话、构建和 HDC 转发表，逐请求记录实际入口和内核身份；记录 P50/P95/P99、TTFB、成功率、下载速率及 RSS。 |
| 启动页修复 | Ability 同步注册生命周期，物理网络发现不占用 WindowStage 队列。真机已确认进入首页；增加网络发现悬而未决时仍能继续初始化的回归测试。 |

## 三内核同条件测量

同一手机、物理网络 netId 279、同一配置和同一节点指纹，全局模式；100 次 HTTPS，4 并发，12 秒超时，5 次预热排除。下载为 1 MiB 单流和 4 个并发的 1 MiB 流。请求实际进入各自内核的专属原生端口，HDC 转发在请求前后校验。

| 内核 | 成功数 | P50 / P95 / P99 ms | RSS 漂移 MiB | 1 MiB 单流速率 MiB/s | 四流合计 MiB/s |
| --- | --- | --- | --- | --- | --- |
| Mihomo 1.10.0 | 100/100 | 894 / 2906 / 5525 | +4.699 | 0.657 | 1.291 |
| Meow 0.21.2 | 98/100 | 690 / 3818 / 6501 | -0.770 | 0.425 | 1.078 |
| sing-box 1.13.21 | 98/100 | 808 / 2817 / 3751 | +1.742 | 0.651 | 0.636 |

Meow 和 sing-box 各有 2 次客户端 TLS 提前结束，未达到 99% 门槛。原因未被逐请求定位到具体远端关闭事件，不能据此声称插件兼容已完全修好，也不能直接归因于节点。三者的单流和四流样本下载均完成。

这不是同一错误重复计数。Meow 为请求 68、83，耗时 5,240 / 5,259 ms；sing-box 为请求 29、88，耗时 5,387 / 4,515 ms。四个请求都未完成 TLS，目标 HTTP 状态为 0、返回正文为 0，未达到 12 秒客户端超时，测试会话未重启。缺少这些请求同期的逐 socket 日志，尚不能判定本地适配器、代理节点或目标链路中的关闭方；“各两次”只是本轮计数，未证明存在固定两次的机制。明细见 `dist/TinyPaws-1.2.8-failed-request-audit.json`。

这些是本次网络条件下的小样本测量，不是耗电、极限带宽或所有网站的排名。测试包含 HDC 和桌面 curl 开销；首轮本地编译与部分测量重叠，时间顺序及外部网络波动也限制了精细性能比较。没有据此作出谁“最强”的结论。

Mihomo 的实际节点在控制器连接链中被观察到。Meow 没有启用独立原生控制器，本轮主机与代理出口指纹相同，故其报告没有将出口变化计为独立路由证明；它的成功请求数只证明命名原生内核入口的数据路径。sing-box 的路由证据以其报告为准。

测试构建启用了候选诊断开关；发布包关闭该开关并新增只读分层探测/诊断导出。构建指纹写入各自报告，不将诊断构建的测试记录直接导入发布包准入。

- `dist/TinyPaws-1.2.8-{mihomo,meow,sing-box}-100.json`：逐请求数据及条件。
- `dist/TinyPaws-1.2.8-final-release-smoke.json`：发布包重新连接验证。
- `dist/TinyPaws-http-obfs-compatible-local.json`：独立服务端解密请求、加密响应、分段头完整往返。
- 受旧 HDC 转发污染的早期失败报告已剔除。HDC 即使输出 `[Fail]` 也可能返回退出码 0，工具现在同时检查输出和实际转发表。

## 构建、检查与清理

```sh
scripts/verify.sh
HAP_BUILD_MODE=release scripts/package-hap.sh
python3 scripts/clean-generated.py              # 预览
python3 scripts/clean-generated.py --apply      # 编译和测试完成后执行
```

构建依赖包括 DevEco SDK/NDK、ohrs/Rust、匹配的 `FlClash-ohos-upstream` Mihomo 库、`sing-box-ohos` 和 OpenHarmony Go 工具链。构建脚本保留并校验必要补丁；第三方说明见 `THIRD_PARTY_NOTICES.md`。

本轮验证：工作区 621 项通过；新增诊断允许名单和分层探测有针对性回归；ArkTS 48/48，基准工具 5/5，物理 DNS 转换 Go 测试通过，HTTP-obfs 独立完整往返通过；鸿蒙发布打包通过。15 个本地协议 fixture 启动也通过，该项不冒充真机协议验收。

清理移除了约 15 GiB 增量缓存、过期 fixture、诊断临时包和被替代的报告。编译依赖、release 库、SDK、外部源码、地理数据、签名材料、1.2.7 回退包及最终包保留。清理后已重新打包成功。明细见 `dist/TinyPaws-1.2.8-cleanup.json`。

## 尚未放行的验收

候选需要匹配当前内核/构建/配置/节点的完整记录：100 次至少 99 成功、10,000 次至少 9,950 成功、稳态 RSS 增长小于 20 MiB、进程与路由证据、应用验证、8 小时锁屏及网络切换。未完成或未通过的项目不会被填写成成功。本版继续以 Mihomo 作为生产默认。
